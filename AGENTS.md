# AGENTS.md

## 1. Project Overview & Tech Stack
- **Context:** Mealie is a self-hosted recipe manager, meal planner, and shopping-list application for households and families. It imports recipes from URLs, organizes recipes into cookbooks, and exposes a REST API for third-party integrations; users and resources are organized into groups and households.
- **Core Stack:** Python `>=3.12,<3.13`, FastAPI, Uvicorn, Pydantic 2/pydantic-settings, SQLAlchemy 2, Alembic, and setuptools; SQLite by default or PostgreSQL through the `pgsql` extra/psycopg2. Frontend: TypeScript/JavaScript, Vue 3, Nuxt `^3.19.2`, Vite `^7.0.0`, Vuetify `^3.9.7`, VueUse, Axios, Nuxt i18n, Nuxt Fonts, PWA support, CSS/SCSS, and Sass Embedded. Tooling: uv, Go Task v3, Yarn Classic 1.22.22, Ruff, mypy, pytest, ESLint 9, Prettier 3, Vitest 3, Docker Compose, and MkDocs Material. Frontend CI uses Node 22; the Docker frontend builder uses Node 24. TODO: Specify the supported local Node range; the frontend manifest has no `engines` field.

## 2. Directory Map & Entry Points
**Key Folders:**
- [mealie/routes/](mealie/routes/): REST endpoints; [mealie/routes/_base/](mealie/routes/_base/) contains class-based controllers, router classes, and CRUD handling. [mealie/routes/__init__.py](mealie/routes/__init__.py) registers the `/api` router tree.
- [mealie/services/](mealie/services/): Recipe processing, imports, backups, notifications, and scheduled work; [mealie/services/scheduler/](mealie/services/scheduler/) owns background scheduling.
- [mealie/repos/](mealie/repos/): SQLAlchemy data access and repository factories, including group/household scoping; [mealie/db/models/](mealie/db/models/) defines ORM tables and relationships.
- [mealie/schema/](mealie/schema/): Pydantic request/response/domain schemas; [mealie/schema/_mealie/mealie_model.py](mealie/schema/_mealie/mealie_model.py) defines the shared API model and alias conventions.
- [mealie/core/](mealie/core/): Settings, security, dependencies, logging, and exceptions; [mealie/alembic/](mealie/alembic/) contains migration configuration and version history.
- [mealie/pkgs/](mealie/pkgs/) and [mealie/scripts/](mealie/scripts/): Supporting packages and operational scripts; [mealie/assets/](mealie/assets/) contains packaged assets; [mealie/lang/](mealie/lang/) contains backend localization.
- [frontend/pages/](frontend/pages/), [frontend/layouts/](frontend/layouts/), [frontend/middleware/](frontend/middleware/), and [frontend/plugins/](frontend/plugins/): Nuxt file-based routes, page shells, route guards, and application initialization. Shopping lists live under [frontend/pages/shopping-lists/](frontend/pages/shopping-lists/); the planner lives under [frontend/pages/household/mealplan/](frontend/pages/household/mealplan/).
- [frontend/components/Domain/](frontend/components/Domain/), [frontend/components/global/](frontend/components/global/), and [frontend/components/Layout/](frontend/components/Layout/): Feature components, shared `Base*` controls, and application layout components; see [frontend/components/README.md](frontend/components/README.md).
- [frontend/composables/](frontend/composables/): Reactive application/feature state; [frontend/lib/api/](frontend/lib/api/) contains typed API clients and schema-derived types; [frontend/server/](frontend/server/) contains Nuxt server routes, including API proxying.
- [frontend/assets/](frontend/assets/), [frontend/static/](frontend/static/), [frontend/lang/](frontend/lang/), and [frontend/content/](frontend/content/): Shared styling, public assets, localization, and bundled changelog content. The UI contract is [frontend/DESIGN.md](frontend/DESIGN.md).
- [tests/unit_tests/](tests/unit_tests/), [tests/integration_tests/](tests/integration_tests/), and [tests/multitenant_tests/](tests/multitenant_tests/): Python unit, API integration, and tenant-isolation tests; [tests/fixtures/](tests/fixtures/), [tests/utils/](tests/utils/), and [tests/data/](tests/data/) provide shared support. [tests/e2e/](tests/e2e/) contains end-to-end infrastructure; frontend Vitest tests are also colocated with composables/plugins and under [frontend/tests/](frontend/tests/).
- [dev/code-generation/](dev/code-generation/): Schema exports, TypeScript bindings, locale registrations, pytest routes/data paths, and API documentation generators; [dev/data/](dev/data/) holds development application data.
- [docker/](docker/), [.devcontainer/](.devcontainer/), [.github/workflows/](.github/workflows/), and [.vscode/](.vscode/): Container packaging/services, development environment, CI/release automation, and editor tasks.
- [docs/](docs/): MkDocs configuration and contributor/user/API documentation; [openspec/changes/](openspec/changes/) and [openspec/specs/](openspec/specs/) contain change artifacts and specifications, configured by [openspec/config.yaml](openspec/config.yaml).
**Entry Points:**
- [mealie/main.py](mealie/main.py): Installed `mealie` CLI entry, declared in [pyproject.toml](pyproject.toml), starts Uvicorn with `mealie.app:app`. [mealie/app.py](mealie/app.py) constructs FastAPI, registers routers/static serving, initializes the database, and registers scheduled work through its lifespan.
- [frontend/nuxt.config.ts](frontend/nuxt.config.ts): Nuxt application/build configuration with `ssr: false`; routing starts through [frontend/pages/index.vue](frontend/pages/index.vue) and the pages/layouts conventions, not a hand-written root `App.vue`. [frontend/plugins/axios.ts](frontend/plugins/axios.ts), [frontend/plugins/init-auth.client.ts](frontend/plugins/init-auth.client.ts), and [frontend/plugins/theme.ts](frontend/plugins/theme.ts) initialize API transport, authentication, and Vuetify themes.
- [docker/entry.sh](docker/entry.sh): Production container startup; [dev/code-generation/main.py](dev/code-generation/main.py): Generator dispatcher.

## 3. Critical Commands
Commands below run from the repository root unless explicitly prefixed with `cd frontend &&`. Their sources are [Taskfile.yml](Taskfile.yml), [frontend/package.json](frontend/package.json), and the [backend](.github/workflows/test-backend.yml)/[frontend](.github/workflows/test-frontend.yml) CI workflows.
- **Dependency Setup:** `task setup` installs both stacks; `task setup:py` runs `uv sync --extra pgsql --group dev` and installs pre-commit; `task setup:ui` installs frontend dependencies with Yarn. Frontend ESLint imports generated Nuxt configuration: `cd frontend && yarn nuxt prepare` is the CI preparation command. Python LDAP dependencies require native libraries; Linux CI installs `libsasl2-dev libldap2-dev libssl-dev`. TODO: Record supported native-library installation commands for macOS/Windows outside the dev container.
- **Build / Compile:** `task ui:build` runs the Nuxt build; `task ui:generate` generates the static SPA in `frontend/dist`; `task py:package` builds wheel/sdist in `dist` and exports pinned requirements, generating and copying the frontend into the Python package first. `task docker:prod` builds and starts the production Compose stack; `task docker:build-from-package` builds the image from Python packages.
- **Dev Server:** `task py` starts the backend on port 9000; `task ui` starts Nuxt, normally on port 3000; `task dev:services` starts PostgreSQL and Mailpit; `task py:postgres` selects the development PostgreSQL settings; `task docs` generates API docs and starts MkDocs. Root tasks load [.env files as configured in Taskfile.yml](Taskfile.yml) and set development defaults, including `PRODUCTION=false` and `BASE_URL=http://localhost:3000`.
- **Lint / Format:** `task py:lint`; `uv run ruff format . --check` for a non-mutating format check; `task py:format` to rewrite Python formatting; `task ui:lint` enforces zero frontend warnings. From the frontend directory, [frontend/DESIGN.md](frontend/DESIGN.md) also specifies `node_modules/.bin/eslint` for changed files. `uv run pre-commit run --all-files` runs the hooks configured in [.pre-commit-config.yaml](.pre-commit-config.yaml), some of which rewrite files.
- **Typecheck:** `task py:mypy` runs `uv run mypy mealie`. TODO: Define the canonical frontend typecheck command; neither the frontend scripts nor the Taskfile exposes one, and frontend CI runs preparation, lint, and Vitest, not a separate typecheck.
- **Testing:** `task py:test` or `uv run pytest`; arguments pass through, for example `task py:test -- tests/unit_tests/schema_tests/test_meal_plan.py`. `cd frontend && yarn test:ci` is the non-watch frontend check; `task ui:test` runs Vitest in watch mode. For a focused existing suite: `cd frontend && node_modules/.bin/vitest run composables/recipes/use-recipe-comparison.test.ts`. `task py:coverage` runs pytest, reports coverage, generates HTML, and opens it. Python discovery/configuration lives in [pyproject.toml](pyproject.toml); Vitest uses globals, jsdom, and `@`/`~` aliases in [frontend/vitest.config.js](frontend/vitest.config.js).
- **Combined Checks / Generation:** `task py:check` runs formatting, Ruff, mypy, and pytest, so it is not read-only; `task ui:check` includes watch-mode tests. `task dev:generate` runs all generators, API docs generation, and repository-wide Python formatting; `task dev:generate -- types` selects the types generator but still generates docs and formats Python. Generator keys are `schema`, `types`, `locales`, `data-paths`, and `routes`. `task docs:gen` regenerates API documentation.
- **Test Preconditions:** [tests/conftest.py](tests/conftest.py) sets `PRODUCTION=True`, `TESTING=True`, `ALLOW_SIGNUP=True`, and a dummy OpenAI key, initializes the database during import, overrides the API session dependency, and attempts cleanup of `tests/.temp`; the API-client fixture unlinks the active SQLite database on teardown. Use isolated test data/database settings, never a live application database. Backend CI exercises SQLite and PostgreSQL and supplies PostgreSQL and LDAP services; a local run without those services does not reproduce that full matrix.

## 4. Code Style & Technical Conventions
- **State Management / Data Flow:** Backend routes use `@controller` class-based views, FastAPI dependencies, base controllers, repositories, and optional service delegation. Reuse [mealie/repos/all_repositories.py](mealie/repos/all_repositories.py) and repository factories rather than bypassing group/household scope. ORM models belong in the database layer; API models derive from `MealieModel`, whose aliases expose camelCase fields from Python snake_case. Schema changes affect frontend bindings, API docs, and migrations when persistent structure changes; see [database-changes.md](docs/docs/contributors/developers-guide/database-changes.md).
- **State Management / Data Flow:** Frontend state uses Vue Composition API refs/computed values and composables, including the factories under [frontend/composables/partials/](frontend/composables/partials/) and stores under [frontend/composables/store/](frontend/composables/store/); [frontend/store/index.js](frontend/store/index.js) is a stub, not an active Vuex architecture. Use existing authenticated/public/admin API clients under [frontend/lib/api/](frontend/lib/api/) and their composables. Nuxt auto-imports components with `pathPrefix: false`; preserve existing names rather than assuming folder-derived prefixes.
- **Error Handling:** Backend controllers use domain exceptions from [mealie/core/exceptions.py](mealie/core/exceptions.py), registered translated CRUD exceptions, and FastAPI `HTTPException` for HTTP failures; validation handling lives in [mealie/routes/handlers.py](mealie/routes/handlers.py). Use the existing logger from [mealie/core/root_logger.py](mealie/core/root_logger.py) or controller/service logger; Ruff enables print/debugger checks. Preserve session closing/rollback patterns in the owning database/repository implementation.
- **Error Handling:** [frontend/plugins/axios.ts](frontend/plugins/axios.ts) attaches bearer tokens, displays response/error notifications, and clears authentication/redirects on 401. Preserve API client result/error contracts instead of adding a second notification/authentication mechanism. ESLint rejects prop mutation and raw `v-html`; existing rendered Markdown uses [frontend/components/global/SafeMarkdown.vue](frontend/components/global/SafeMarkdown.vue).
- **Formatting:** Python uses Ruff targeting `py312`, a 120-character line limit, isort import ordering, and complexity limit 24; selected rule families and per-file exemptions are in [pyproject.toml](pyproject.toml). Mypy targets Python 3.12 with the Pydantic plugin, skipped imported-module checking, ignored missing imports, and strict optional checking. Do not infer a repository-wide strict typing requirement from those settings.
- **Formatting:** [frontend/.editorconfig](frontend/.editorconfig) specifies two spaces, UTF-8, LF, final newlines, and trailing-whitespace trimming except for Markdown. Nuxt ESLint stylistic settings require semicolons, double quotes, two-space indentation, and multiline trailing commas; [frontend/.prettierrc](frontend/.prettierrc) separately specifies width 120, ES5 trailing commas, and parenthesized arrow parameters. Follow the active ESLint result where these differ; [frontend/eslint.config.mjs](frontend/eslint.config.mjs) permits explicit `any` and limits Vue attributes to five on a single line or one per multiline line.
- **Components / Styling:** Shared controls use `Base*`; domain components use domain prefixes; layout components conventionally use `App*` when accepting props and `The*` otherwise. [frontend/components/README.md](frontend/components/README.md) describes flat global/layout folders, but existing layout subfolders exist: do not move them merely to enforce that prose. Runtime palettes belong in [frontend/plugins/theme.ts](frontend/plugins/theme.ts), shared tokens/states in [frontend/assets/main.css](frontend/assets/main.css), and font loading in Nuxt Fonts configuration; do not treat [frontend/vuetify.options.js](frontend/vuetify.options.js) as the runtime palette owner.
- **UI Contract:** Follow [frontend/DESIGN.md](frontend/DESIGN.md): Plus Jakarta Sans body/controls, Lora display titles, semantic Vuetify colors, retained custom themes/dark preferences, cards at most 8px radius, unframed sections, labeled actions/fields, and main controls at least 44px high. Use shared motion tokens and reduced-motion handling. Distinguish an empty library from no matching results; do not fabricate recipe counts/images. UI changes require light/dark checks at 375, 768, 1024, and 1440px, including overflow, actual image/font loading, and relevant keyboard/form/navigation behavior.
- **Documentation / Changes:** API changes require documentation updates per [code-contributions.md](docs/docs/contributors/developers-guide/code-contributions.md); the same guide requires passing checks, Conventional Commit-style PR titles, and release notes. The in-app changelog is [frontend/content/changelog.md](frontend/content/changelog.md), rendered by [frontend/pages/changelog.vue](frontend/pages/changelog.vue); prepend implemented changes and keep unreleased entries labeled `Unreleased`. Existing OpenSpec change artifacts are under [openspec/changes/](openspec/changes/); the config uses `spec-driven`, but does not define mandatory proposal triggers. ## 5. System Guardrails & Boundaries
- **Restricted Areas:** NEVER run `task dev:clean`, delete application data/backups/secrets, or run tests/migrations against a live database without explicit user permission. The cleanup task explicitly removes development recipes, users, SQLite files, logs, and the signing secret; these are not interchangeable with disposable build artifacts. Preserve unrelated worktree changes.
- **Restricted Areas:** Generated boundaries include TypeScript API definitions derived from schema modules, [frontend/types/components.d.ts](frontend/types/components.d.ts), generated schema exports/test helpers, and `CODE_GEN_ID`/`END` registration blocks in the Nuxt/i18n configuration. Change the owning schema/generator and regenerate; do not silently hand-edit generated output. [frontend/lib/api/types/non-generated.ts](frontend/lib/api/types/non-generated.ts) is the explicit handwritten types exception. Locale generation uses [dev/code-generation/gen_ts_locales.py](dev/code-generation/gen_ts_locales.py); preserve its markers and distinguish editable message sources from generated locale registrations. Full generation rewrites multiple areas and may access Crowdin.
- **Restricted Areas:** TODO: Maintainers must define the approval-required source/configuration paths, including whether [.github/workflows/](.github/workflows/), [mealie/alembic/versions/](mealie/alembic/versions/), [uv.lock](uv.lock), [frontend/yarn.lock](frontend/yarn.lock), [docker/](docker/), and [LICENSE](LICENSE) require explicit permission. No existing blanket prohibition for these paths was found; do not claim one is already repository policy. Database migration procedures are documented in [database-changes.md](docs/docs/contributors/developers-guide/database-changes.md); use them when a schema change is authorized.
- **Security Context:** Authentication includes credentials/bcrypt, bearer JWTs and the `mealie.access_token` cookie, LDAP, OIDC, and stored long-lived tokens. Backend dependencies/controllers enforce user/admin permissions; frontend route guards are not an authorization substitute. Preserve group/household scoping and extend [tests/multitenant_tests/](tests/multitenant_tests/) when cross-tenant access behavior changes. Do not weaken auth dependencies or substitute unfiltered repositories in user-facing endpoints.
- **Security Context:** Settings use environment configuration and Docker secrets under `/run/secrets`; production signing/session secrets are persisted as `.secret` and `.session_secret` in `DATA_DIR`. Preserve the masking serializer for sensitive settings in [mealie/core/settings/settings.py](mealie/core/settings/settings.py). Do not log or commit real tokens, passwords, secret files, database URLs with credentials, or OpenAI/Crowdin keys; keep secrets out of Nuxt `runtimeConfig.public`. Development/test defaults are not production credentials.
- **Security Context:** Follow [SECURITY.md](SECURITY.md) for vulnerability reporting; non-public details go through its maintainer contact rather than a public issue. The project license is `AGPL-3.0-only` in [pyproject.toml](pyproject.toml).
